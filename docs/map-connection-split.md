# Вставка муфты в существующее соединение

> Продолжение реализации: [объекты и способы прокладки на трассе](map-infrastructure-routes.md).
> Split теперь поддерживает разрешённые типы узлов, сохраняя совместимость
> приведённого ниже старого payload. Изменения схемы и новые проверки описаны там.

Реализовано 28 октября 2026. Изменений таблиц, миграций, новых ролей,
пространственных индексов или провайдера карты нет.

## API

`POST /api/v1/map/connections/{id}/split`, ответ `201`:

```json
{
  "expected_version": 3,
  "expected_geometry_token": "<64 hexadecimal characters from connection response>",
  "segment_index": 1,
  "fraction": 0.37,
  "position": {"latitude": 55.58, "longitude": 38.25},
  "marker": {"name": "Муфта М", "description": null, "icon_name": "splice"}
}
```

В примере `position` условная: настоящий запрос обязан передать точку указанного
сегмента. `marker` принимает описательные поля и существующий строго валидируемый
`MapMarkerAppearance`. Тип `splice`, отсутствие связи с домом, координаты,
компания, видимость и владелец устанавливаются сервером. Передать их внутри
`marker` нельзя (`extra=forbid`).

Ответ: `{marker: MapMarkerResponse, connections: [MapConnectionResponse,
MapConnectionResponse]}`. Первый участок сохраняет исходный ID, увеличивая
версию; второй получает новый ID и версию 1. Остальные записи графа не меняются.
Имя, описание, среда, статус, число волокон / категория кабеля и владение
копируются в оба участка. Отдельной модели сварок, портов или волокон нет.

Ответы существующего API соединений дополнены `geometry_token`. Это SHA-256
канонической геометрии с текущими координатами концов (точность 7 десятичных
знаков), не секрет и не механизм авторизации. Старые поля не изменены. Токен
обнаруживает перемещение дома/узла даже без изменения версии самой линии.

## Транзакция и доступ

1. Действуют прежние JWT, `X-Company-Id` и `addresses.read`.
2. Берётся существующий advisory lock компании, затем строка соединения.
3. Применяются `visible_to`, `require_write`, `check_version`.
4. Создание технической муфты требует `addresses.manage`, как обычное создание
   технического маркера. Право редактировать собственную личную линию само по
   себе не разрешает создавать технические объекты. Чужие личные линии остаются
   недоступны даже администратору.
5. Концы блокируются до конца транзакции: сначала дома в порядке ID, затем
   самостоятельные маркеры в порядке ID. Геометрия перечитывается после блокировок.
6. Проверяются версия, снимок, сегмент, положение, длины участков.
7. Создаётся самостоятельный `MapMarker(point_type="splice")`, изменяется первый
   участок, добавляется второй. Формируются ответы, затем выполняется единственный
   `commit`. Любая ошибка приводит к `rollback`, включая ошибку вставки второго
   участка. Повторный/конкурентный запрос со старой версией получает `409`.

Личная линия порождает личную муфту и два личных участка того же владельца;
общая линия — общие записи без владельца. Пересечение/наложение другого кабеля
не означает его подключения к новой муфте.

## Геометрия и ограничения

- `segment_index` относится к полной последовательности: источник, внутренние
  вершины, назначение. Не к обрезанному/упрощённому результату hit-testing.
- `fraction` — доля в Web Mercator. Это сохраняет прямой отрезок MapLibre при
  вставке; линейная интерполяция широты была бы некорректна.
- `position` проверяется с допуском 5 см на округления. Сервер не переносит
  произвольную точку пользователя на линию молча. В БД сохраняется вычисленная
  точка с существующей точностью координат `Numeric(..., 7)` (около сантиметра).
- Каждый новый участок должен иметь длину по трассе не менее 1 м.
- Нулевой выбранный сегмент отклоняется. Вставка в изгиб допустима: его вершина
  становится концом, без лишней копии во внутренних вершинах.
- Вставка вне Mercator ±85.05112878° и в сегмент, пересекающий линию перемены
  дат (разница долгот >180°), явно отклоняется `422`. Существующие записи не
  переписываются и не удаляются.
- Нет отдельной истории происхождения участков и автоматического обратного
  слияния при удалении муфты. Прежние FK запрещают удалять связанный узел.

## Проверки

Полный `pytest -vv`: **528 passed**, Python 3.13, реальный PostgreSQL 18.6
и Redis 8 в отдельных тестовых контейнерах. Существующий
`tests/authorization/test_map_graph_api.py` сохранён и проходит (16 тестов).

типов концов, точность позиции, недопустимые/нулевые сегменты, повторный запрос,
параллельные независимые PostgreSQL-транзакции, откат после создания муфты при
ошибке второго участка, JWT/RBAC, реальный контекст второй компании, удалённую
линию и отсутствие подключения пересекающегося кабеля.

`docker compose config --quiet` и `git diff --check` проходят.
Действующие development volumes и данные не изменялись.
