# Визуальные границы прокладки — 29 октября 2026

## Совместимость и хранение

Схема PostgreSQL **не меняется**. Миграция, DDL и пересоздание development DB
не нужны. Используется существующий JSONB `installation_methods`: один способ
на каждое ребро `[source, *vertices, target]`. Старый пустой массив продолжает
означать `unknown`. Граница — внутренняя вершина, у которой способы соседних
рёбер различаются. Это не MapMarker и не новый конец сетевого соединения.

Добавление прежним `POST /map/connections/{id}/installation-boundaries`
сохранено без изменения контракта. Split, размещение объектов, общий PATCH
трассы и правила владения/видимости не заменяются.

## Новый endpoint

`PATCH /api/v1/map/connections/{id}/installation-boundaries/{vertex_index}`

`vertex_index` — индекс точки в **полной** геометрии текущего snapshot, не ID
физического объекта. Все операции требуют `expected_version` и
`expected_geometry_token`. Discriminated union, `extra=forbid`:

- `operation: "set"`, `installation_after`: изменить текущий участок после
  выбранной границы до следующей границы (не до произвольной вершины).
- `operation: "remove"`, `keep: "previous" | "next"`: явное объединение двух
  соседних участков. Физическая вершина сохраняется, чтобы не срезать поворот.
- `operation: "move"`, `segment_index`, `fraction`, `position`:
  перенести границу по существующей полилинии. Старая вершина сохраняется;
  в новой позиции при необходимости добавляется коллинеарная вершина.

Ответ — актуальный `MapConnectionResponse`, включая новую версию, геометрию,
token, способы прокладки и актуальные привязки объектов.

## Инварианты

Используется `_locked_route`: JWT/company visibility → company advisory lock →
FOR UPDATE → `require_write` → версия → упорядоченные блокировки концов →
проверка token по **актуальным** координатам. Требуется существующее право
управления инфраструктурой; приватная линия другого владельца остаётся 404.

Для переноса используется прежняя Mercator-проверка точки (допуск 5 см),
проверка ненулевого сегмента и отступ 1 м от концов. Дополнительно запрещены
пересечение соседних границ и участки короче 1 м между ними. Лимит — прежние
498 промежуточных вершин. Сервер не доверяет координатам и порядку клиента.

`reanchor_route` перепроверяет фиксированные объекты трассы. Версия, вершины,
способы и привязки сохраняются одной транзакцией; исключение вызывает rollback.
Повторная/параллельная операция со старой версией получает 409. Изменение
метаданных не меняет концы, тип кабеля, видимость, слои или паспорт.

## Ограничения

Перенос не упрощает старые вершины автоматически: они сохраняют точную форму
трассы и расходуют существующий лимит. При его достижении возвращается 422,
а не удаляются чужие геометрические точки. Индекс границы действителен только
с её version/token; вечные идентификаторы границ и отдельная таблица не нужны.
